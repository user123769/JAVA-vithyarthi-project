Electricity-Bill-Generation- A modular Java application that can calculate, manage and analyze household electricity consumption and billing with tiered tariff rates. The Java application helps users keep track of how much electricity's used in a home and shows them how much they will pay each month. #Overview- This desktop or command line interface Java application lets users manage household appliances calculate estimated power bills using slab-based pricing and view energy consumption breakdowns. #Featuers- Appliance Management (Create, Read, Update, Delete): Add, see, edit and delete appliances with wattage ratings and daily usage hours. Dynamic Tariff Engine: Computes bills using tiered slabs, fixed charges and tax additions. Consumption Analytics: Provides energy usage breakdowns in kWh, per device. Cost Forecasting: Calculates predicted costs based on average usage patterns. #Technologies Used- Language: Java (JDK 17 and above). I enjoy using Java for its robustness. Build Tool:. Gradle. I prefer Maven for its simplicity. Database:. Mysql (using JDBC). I like SQLite for prototypes. GUI / Interface: JavaFX or Swing or a command line interface. I enjoy JavaFX for its look. Testing: JUnit 5. I use JUnit 5 for unit tests. #How to install and run the project- The installation and execution lifecycle of the Electricity Bill Estimator relies on Java Development Kit (JDK 17+) to compile source code and to run it. It also uses Apache Maven to manage dependencies automatically and to build the project. The process begins when the source code is fetched from Git, which establishes file ownership. Next Maven reads the pom.xml configuration file to resolve required libraries compile Java files into JVM-compatible bytecode (,.class files) and put them into the output directory during the compilation phase. Finally the Java Virtual Machine (JVM) initializes the runtime environment. Calls the entry-point main() method of the Electricity Bill Estimator. Developers can also run JUnit test suits before runtime to validate the integrity of the Electricity Bill Estimator system and to check unit calculations automatically. #Instruction for testing- Software testing is my job to keep the system reliable, accurate and stable before it goes live. In the Electricity Bill Estimator project I focus on the core business logic. I make sure that the multi-tiered slab calculations, the fixed charges and the appliance consumption formulas are mathematically correct even when the numbers are, at the edge. *Unit Testing: I test each component for example the BillCalculator and Appliance classes, on its own using the JUnit 5 framework. Unit Testing makes sure that the math functions, such as turning Watts and hours into 𝑘𝑊ℎgive the right results no matter what the database or user interface does. *Boundary Value Analysis: I check the edge cases like the switch between electricity slabs at numbers such as 100 units, 101 units or 0 units. Boundary Value Analysis helps me make sure that the right rate tier is used and that there are no off-by-one mistakes. *Input Validation & Exception Handling: I test how the app behaves when it receives data for example a negative wattage, usage hours that are more, than 24 a day or missing tariff settings.
